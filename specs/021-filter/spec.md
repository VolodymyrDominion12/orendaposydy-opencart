## Проблема
У категорії зараз лише сортування. Фільтрів немає: таблиці фільтрів ядра порожні (0 груп, 0 значень), а атрибути (Матеріал, Колір, Розмір,
Об'єм, Серія / стиль — 273 значення на 140 товарах) записані вільним текстом («Скло, метал», «Сталь, PVD-покриття»), по ньому відібрати не можна.
Клієнт, якому треба «білі порцелянові тарілки 27 см» або «прозорі стільці», гортає всю категорію. З реальним прайсом (сотні позицій, 022)
це стане головною незручністю. Крім того, концепція передбачає посадкові сторінки під запити на кшталт «оренда білих тарілок» — зараз їх немає.

## Мета і метрика
- У категорії звузити вибір до потрібного за 1–3 дотики, не втрачаючи сторінку й прокрутку; на телефоні — шторка з «Показати N товарів».
- Кожен варіант показує, скільки товарів залишиться (лічильник), тупикових варіантів «0 товарів» немає.
- Фільтровані адреси не плодять дублі в індексі; індексуються лише вибрані комбінації з власним `h1`/`title`/текстом.
- Категорія з фільтрами — у бюджеті `≤ 100` запитів, без N+1; `make test-mobile` у бюджеті.

## Користувачі та сценарії
- **Як** клієнт із телефону, **я хочу** натиснути «Фільтри», відмітити «Порцеляна» і «Білий» і побачити «Показати 5 товарів», **щоб** не гортати всю категорію.
- **Як** клієнт на десктопі, **я хочу** відмічати значення в бічній колонці й одразу бачити оновлений список без перезавантаження сторінки.
- **Як** клієнт, **я хочу** обмежити ціну за добу «від–до», **щоб** вкластися в бюджет події.
- **Як** клієнт, **я хочу** надіслати менеджеру посилання на відфільтрований список, **щоб** він бачив те саме.
- **Як** адміністратор, **я хочу** призначати товарам значення фільтрів у картці товару (і масово), **щоб** нові товари одразу потрапляли у фільтри.
- **Як** SEO-фахівець, **я хочу** створити сторінку «Оренда білих тарілок» = категорія «Тарілки» + фільтр «Білий» з власною адресою, `h1`, `title` і текстом.

## Критерії приймання
- **AC-1. Групи і значення.** Given в адмінці ядра «Каталог → Фільтри» є групи (Матеріал, Колір, Серія / стиль, Розмір, Об'єм…), а товарам призначено значення,
  Then у категорії показуються лише групи, у яких серед товарів, що показує категорія (як у списку ядра: товари, прив'язані саме до неї), є ≥ 2 різні значення,
  або є вибране значення; значення без товарів не показуються.
  Порядок груп і значень — `sort_order` ядра. Категорія, де груп для показу немає, виглядає як зараз (без колонки й кнопки «Фільтри»).
- **AC-2. Логіка відбору.** When відмічено кілька значень однієї групи, Then показуються товари з **будь-яким** із них (АБО); між групами — **усі** умови (І).
  Приклад: «Порцеляна + Кераміка» і «Білий» → білі порцелянові або білі керамічні. Відбираються лише увімкнені товари магазину `store_id = 0`.
- **AC-3. Лічильники.** Then біля кожного значення — кількість товарів, яка буде, якщо його додатково відмітити (з урахуванням вибраного в **інших** групах);
  значення, що дасть 0, показується неактивним (не прибирається, щоб список не «стрибав»). Вибрані значення завжди активні.
- **AC-4. Ціна за добу.** Then група «Ціна за добу, ₴» з двома полями «від–до»; межі за замовчуванням — мінімальна й максимальна ціна товарів категорії
  (з урахуванням інших фільтрів); товари без ціни при заданому діапазоні не показуються. Нечислове або перевернуте «від > до» значення виправляється, а не дає помилку.
- **AC-5. Десктоп (≥ 1024 px).** Then фільтри — бічна колонка зліва від сітки, як у макеті; групи згортаються (`details`); When відмітити значення,
  Then список, кількість «N товарів», лічильники й адреса в рядку браузера оновлюються без перезавантаження (≤ 300 мс локально), прокрутка не скидається.
  Над сіткою — вибрані значення «плашками» з хрестиком і «Скинути всі».
- **AC-6. Мобільний (< 1024 px).** Then над сіткою кнопка «Фільтри» з кількістю вибраних; When натиснути, Then шторка знизу (`k-sheet`) з групами, внизу «Скинути»
  і «Показати N товарів» (N оновлюється при кожній відмітці, сітка — лише після «Показати»). Закриття — хрестик, тап по фону, «Назад» у браузері, Esc.
- **AC-7. Адреса.** Then вибір зберігається в адресі латиницею одним параметром, напр. `/posud/tarilky?filter=kolir-bilyi_material-porcelyana_tsina-10-40`
  (уточнено під час планування: параметр `filter` ядро вже протягує в сортування, пагінацію й «Показати ще»);
  порядок значень в адресі не важливий (сайт приводить до одного вигляду), сортування й сторінка зберігаються.
  When відкрити таке посилання в новій вкладці, Then той самий список і ті самі відмітки. Невідомі/видалені значення в адресі ігноруються без помилки.
- **AC-8. Без JS.** Then фільтри працюють як звичайна форма (кнопка «Показати»), сторінка повністю рендериться на сервері; «Показати ще» і пагінація враховують фільтр.
- **AC-9. Нічого не знайдено.** Given комбінація з ціною дає 0 товарів, Then текст «Нічого не знайдено за цими фільтрами», кнопка «Скинути фільтри»
  і блок «Не знайшли — підберемо» (контакти з NAP 019).
- **AC-10. SEO для звичайних комбінацій.** Then сторінка з будь-яким `filter`, що не є SEO-сторінкою фільтра, має `rel="canonical"` на категорію без параметрів
  і `<meta name="robots" content="noindex, follow">`; посилання на значення фільтрів у колонці — з `rel="nofollow"`.
- **AC-11. SEO-сторінки фільтрів.** Given в адмінці «Модулі → Крістал: фільтри → SEO-сторінки» створено сторінку: категорія «Тарілки» + значення «Білий»,
  адреса `bili`, `h1` «Оренда білих тарілок», `title`, `description`, текст. Then:
  `/posud/tarilky/bili` відкривається (200) з цими `h1`/`title`/`description`/текстом, відміченим «Білий», `canonical` на себе, без `noindex`,
  крихти «Головна → Посуд → Тарілки → Оренда білих тарілок»; адреса `/posud/tarilky?filter=kolir-bilyi` віддає **301** на `/posud/tarilky/bili`;
  у колонці фільтрів значення, яке веде на SEO-сторінку, — звичайне посилання (без `nofollow`). Одна комбінація «категорія + значення» — одна сторінка;
  дубль адреси або комбінації адмінка не дає зберегти.
- **AC-12. Адмінка: призначення.** Then у формі товару ядра поле «Фільтри» працює (ядро); у «Крістал: фільтри» — масове призначення:
  вибрати категорію → таблиця товарів × групи з вибором значень → «Зберегти» (≤ 200 товарів на сторінку). Після збереження вітрина показує нове одразу (кеш скинуто).
- **AC-13. Початкове заповнення (мок).** When запустити заповнення з атрибутів (команда `make` або кнопка в «Крістал: фільтри» з переглядом перед записом),
  Then з атрибутів Матеріал / Колір / Серія / стиль / Розмір / Об'єм створюються групи й значення (складені «Скло, метал» → два значення;
  розміри й об'єми → діапазони, див. питання 3) і призначаються товарам; повторний запуск нічого не дублює; є відкат.
- **AC-14. Швидкість.** Then категорія з фільтрами: власних запитів фільтра ≤ 4 на сторінку (товари, лічильники, межі ціни, SEO-сторінка), 0 на повтор (кеш),
  кількість запитів не росте з кількістю товарів і значень; `make db-profile` категорії з 2 відмітками — у бюджеті категорії; AJAX-відповідь ≤ 150 мс на сервері локально.
  Скрипт фільтрів — лише на сторінках категорій, ≤ 6 КБ.
- **AC-15. Безпека.** When у `filter` (та `fv[]`, `pmin`, `pmax` форми без JS) підставити `'`, `<script>`, 500 значень, від'ємні й величезні числа, Then сторінка 200 (або 301 на чисту адресу), нічого не виконується,
  у SQL потрапляють лише цілі id відомих значень; понад 20 значень в адресі ігноруються.
- **AC-16. Доступність.** Then групи — `fieldset`/`legend` або `details` з підписом, чекбокси з `label`, кількість результатів озвучується (`aria-live`),
  шторка — `role="dialog"` з фокусом усередині й поверненням фокуса на кнопку; тач-зони ≥ 44 px, видимий фокус, контраст за брендбуком.

## Нефункціональні вимоги
- **Швидкість:** без запитів на кожен товар чи значення; дані категорії для відбору й лічильників — ≤ 3 запити з індексами на промах кешу, 0 на повтор;
  кеш скидається при зміні товару, фільтра або SEO-сторінки (уточнено в плані: лічильники рахуються по кешованому індексу категорії). `make db-explain` для кожного запиту, `make db-profile` для `/posud`, `/posud/tarilky`, `/posud/tarilky?f=…` і SEO-сторінки до/після.
- **SEO:** один `h1`; `canonical`/`noindex` за AC-10/AC-11; SEO-сторінки потрапляють у sitemap разом з 011 (до того — лише внутрішні посилання з колонки фільтрів);
  `BreadcrumbList` на SEO-сторінці.
- **Мобільна версія:** шторка на 360 px без горизонтального скролу, кнопка «Показати N товарів» завжди видима внизу; `inputmode="numeric"` для ціни;
  `make test-mobile` без `allow` для категорії з фільтрами. На реальному телефоні — шторка, відмітки, «Назад».
- **Ядро не змінюємо:** групи й значення фільтрів — таблиці ядра `oc_filter*`, `oc_product_filter`, `oc_category_filter`; власне — UI, відбір, лічильники, SEO-сторінки.

## Поза межами
- Фільтри на сторінці пошуку (027) і на сторінках подій (006).
- Фільтр «є в наявності на дату» (024).
- Слайдер ціни (лише два поля «від–до»), кольорові «кружечки» замість назв кольорів.
- Шаблони meta з підстановками й sitemap.xml (011) — тут лише поля SEO-сторінки й `canonical`/`noindex`.
- Автоматичне створення SEO-сторінок для всіх комбінацій — лише білий список, який веде людина.
- Фільтри за атрибутами «на льоту» (без призначення значень) — див. питання 1.

## Мок-дані
- Групи й значення фільтрів, згенеровані з атрибутів мок-каталогу 001 (AC-13), — мок агента; клієнт/контент-менеджер перевіряє назви й призначення.
- 2–3 SEO-сторінки фільтрів для перевірки (напр. «Тарілки → Білий», «Стільці → Прозорий», «Келихи для вина → Кришталеве скло») з мок-текстами — замінити текстами SEO-фахівця.
- Локально в підкатегоріях по 4 товари, у розділах 4–18: фільтри перевіряються переважно на розділах («Посуд», «Меблі»); навантаження — на тимчасово розмноженому каталозі (1000 товарів), як у 022.

## Відкриті питання
Закрито 2026-11-10 рішенням людини «погоджую» — пропозиції агента 1–6.

- [x] **1. Джерело фільтрів.** Пропозиція: фільтри ядра (`Каталог → Фільтри`) з призначенням товарам, як у плані архітектури; атрибути лишаються для таблиці
  характеристик на картці. Альтернатива — фільтрувати прямо за атрибутами: не треба вести два місця, але вільний текст («Скло, метал», «23 см» / «23см»)
  дає брудні фільтри й повільні запити. → людина
- [x] **2. Які групи.** Пропозиція: Матеріал, Колір, Серія / стиль, Розмір, Об'єм + Ціна за добу; група показується в категорії автоматично там,
  де є ≥ 2 значення (AC-1), без ручного вибору в кожній категорії. → людина
- [x] **3. Розмір і об'єм.** Пропозиція: діапазонами, як у макеті («до 21 см», «23–27 см», «від 28 см»; для келихів «до 200 мл», «200–350 мл», «від 350 мл»);
  клієнт може перейменувати. Альтернатива — точні значення («23 см», «27 см»): точніше, але довгі списки. → людина
- [x] **4. Прайс (022).** Пропозиція: пізніше окремим кроком додати в CSV-вивантаження колонки груп фільтрів («Колір: Білий; Золото»), щоб клієнт заповнював усе в одному файлі;
  у 021 — лише адмінка (форма товару ядра + масове призначення). → людина
- [x] **5. Формат адреси.** Пропозиція: `?f=kolir-bilyi,material-porcelyana&price=10-40` для звичайних комбінацій і `/категорія/адреса` для SEO-сторінок (AC-7, AC-11).
  Альтернатива — ЧПУ для всіх комбінацій (`/posud/tarilky/kolir-bilyi/material-porcelyana`): красивіше, але тисячі адрес-дублів для пошуковиків. → людина
- [x] **6. SEO-сторінка — скільки значень.** Пропозиція: 1–2 значення (напр. «Білий» + «Порцеляна»), більше — ні. → людина
