## Проблема
Вітрина віддає зображення в PNG/JPEG тих розмірів, які нарізало ядро: головне фото товару 720 px у PNG важить понад 20 КБ навіть як заглушка
(`make test-mobile` → `img_legacy`, виняток до 020), а справжні фото складу будуть JPEG 2–5 МБ (зараз у `image/catalog` 227 файлів, 121 МБ, 44 файли > 500 КБ).
Немає `srcset` — на телефоні з DPR 3 картинка або розмита, або завелика. Ядро вписує непропорційне фото в квадрат з **білими** полями —
на темній темі це білі смуги навколо кожного товару, сфотографованого не в квадрат.

## Мета і метрика
- Усі зображення товарів і категорій на сторінках теми — WebP з `srcset` (1× / 2×) і правильними `width`/`height`.
- Картка товару проходить `make test-mobile` **без `allow`** (зникає `img_legacy`); вага зображень на категорії з 24 товарами ≤ 700 КБ.
- Фото будь-якої пропорції в квадратній картці обрізається по центру (без білих полів).

## Користувачі та сценарії
- **Як** клієнт із телефону, **я хочу** щоб каталог з фото відкривався швидко на мобільному інтернеті, **щоб** не чекати й не витрачати трафік.
- **Як** клієнт, **я хочу** чіткі фото на екрані телефону (DPR 2–3), **щоб** роздивитись посуд.
- **Як** адміністратор, **я хочу** завантажувати фото як є (JPEG з телефона чи камери, будь-якої пропорції), **щоб** не обробляти їх вручну.

## Критерії приймання
- **AC-1. WebP.** Given товар із фото JPEG/PNG, When відкрити категорію й картку в темі `kristal`, Then `<img>` віддає `.webp`; оригінал не змінюється.
- **AC-2. srcset.** Then у картці списку `srcset` «360w, 720w» і `sizes` за сіткою (2/3/4 колонки); головне фото товару — «720w, 1440w»; мініатюри — 1×/2×.
  Then `width`/`height` відповідають пропорції 1:1, CLS ≤ 0.1.
- **AC-3. Обрізання.** Given фото 4:3 або 3:4, Then у квадратній картці воно обрізане по центру, без білих/кольорових полів.
- **AC-4. Оновлення.** Given фото товару замінили в адмінці (той самий файл або новий), When відкрити вітрину, Then показується нове фото (кеш перегенеровано за часом зміни файлу).
- **AC-5. Вага.** Given справжнє JPEG-фото 4000×3000 / 3 МБ, Then версія 360 px ≤ 30 КБ, 720 px ≤ 80 КБ, 1440 px ≤ 220 КБ (якість ~80).
- **AC-6. Без WebP на сервері.** Given PHP без підтримки WebP (немає `imagewebp`), Then вітрина показує JPEG/PNG тих самих розмірів з `srcset`, без помилок і без порожніх картинок.
- **AC-7. Мобільний бюджет.** `make test-mobile` для категорії й картки — без `allow`; `img_kb` категорії ≤ 700.
- **AC-8. Швидкість відповіді.** Перша генерація розмірів не блокує сторінку довше 2 с на 24 товари; повторне відкриття — без генерації (файли з кешу), без запитів до БД.

## Нефункціональні вимоги
- **Швидкість:** генерація — лише при першому зверненні, далі файли з `image/cache/kristal/`; 0 додаткових запитів до БД.
- **SEO:** `alt` = назва товару/категорії (як у 005); імена файлів кешу — латиницею, як у оригіналу.
- **Мобільна версія:** LCP-зображення картки — `fetchpriority="high"`, без lazy; решта — `loading="lazy"`.
- **Сумісність:** PHP 7.3/8.3, GD; без сторонніх бібліотек (Imagick не потрібен).

## Поза межами
- Фотосесія й обробка фото (кольорокорекція, фон) — клієнт; CDN; AVIF; зображення в адмінці; шаблони старої теми `sauco`; зображення в описах (HTML редактора) — 012/013.
- Масове перетворення всіх 227 файлів заздалегідь — генерується при першому показі (опційно — команда прогріву, див. питання 3).
