## Проблема
1. Клієнтам (нареченим, організаторам весіль, корпоративів, ювілеїв) важко самостійно скласти повний набір посуду, приборів, келихів і текстилю на 50, 100 чи 200 гостей. Вони не знають точних норм (скільки тарілок, приборів, бокалів потрібно на гостя) і бояться забути обов'язкові предмети.
2. Ручний пошук і додавання в кошик 10–15 окремих найменувань у великих кількостях займає занадто багато часу та знижує конверсію.
3. Відсутність пакетних рішень («Базовий», «Стандарт», «Преміум») знижує середній чек, оскільки клієнти замовляють лише мінімум, не знаючи про гармонійні преміум-сервірування (наприклад, серії Royal з золотим обідком, золоті прибори, текстиль).

## Мета і метрика
- Надати клієнту готове рішення в 1 клік:
  - 3 рівні сервірування: **«Базовий»** (від 95 ₴/гість), **«Стандарт»** (від 140 ₴/гість — найчастіше обирають), **«Преміум»** (від 230 ₴/гість).
  - Інтерактивний перемикач гостей (50, 100, 200 тощо) з миттєвим перерахунком загальної вартості за добу оренди.
  - Кнопка **«Додати до події»** — пакетно додає всі позиції комплекту у потрібних кількостях до кошика події (`checkout/order`).
  - Кнопка **«Розрахувати подію»** — швидкий перехід до форми ліда `kristal_lead` з передачею обраного комплекту.
- **Ціни не дублюються:** вартість комплекту динамічно вираховується з актуальних цін товарів у каталозі з урахуванням обсягу та опціональної знижки комплекту (`discount_pct`).
- Зростання середнього чеку замовлень на 30–50% та скорочення часу прийняття рішення.

## Користувачі та сценарії
- **Як** наречена або наречений, **я хочу** побачити готовий комплект на 100 гостей на весілля, оцінити його вигляд та бюджет на гостя, **щоб** натиснути одну кнопку і відразу отримати сформований кошторис у кошику без тривалого підбору.
- **Як** організатор або кейтеринг, **я хочу** порівняти стандартний та преміум пакети сервірування, **щоб** швидко показати різницю замовнику.
- **Як** менеджер «Крістал», **я хочу** в адмінці налаштовувати склад комплектів (прив'язка до реальних товарів, кількість на 1 гостя, фіксована кількість, переваги комплекту), **щоб** легко створювати нові пакети під весілля, фуршети, банкети.

## Критерії приймання

### AC-1. База даних комплектів
- Таблиця `oc_kristal_kit`:
  - `kit_id` INT AUTO_INCREMENT PK;
  - `code` VARCHAR(32) NOT NULL UNIQUE (напр., `wedding_basic`, `wedding_standard`, `wedding_premium`);
  - `event_type` VARCHAR(32) NOT NULL (напр., `wedding`, `buffet`, `banquet`, `corporate`);
  - `tier` VARCHAR(32) NOT NULL (`basic`, `standard`, `premium`);
  - `name` VARCHAR(128) NOT NULL;
  - `badge` VARCHAR(64) NULL (напр., `Найчастіше беруть`);
  - `discount_pct` DECIMAL(5,2) DEFAULT 0.00;
  - `features` TEXT NULL (JSON масив пунктів: `[{"text": "...", "included": true/false}]`);
  - `sort_order` INT DEFAULT 0;
  - `status` TINYINT(1) DEFAULT 1;
  - Індекси: `idx_event_tier` (`event_type`, `tier`), `idx_status_sort` (`status`, `sort_order`).
- Таблиця `oc_kristal_kit_item`:
  - `kit_id` INT NOT NULL;
  - `product_id` INT NOT NULL;
  - `qty_per_guest` DECIMAL(8,2) NOT NULL DEFAULT 1.00;
  - `qty_fixed` INT NOT NULL DEFAULT 0;
  - `sort_order` INT NOT NULL DEFAULT 0;
  - PK (`kit_id`, `product_id`);
  - Індекс `idx_product_id` (`product_id`).

### AC-2. Динамічний розрахунок вартості
- Вартість комплекту не зберігається захардкоджена, а обчислюється автоматично:
  `price_per_guest = SUM(product.price * qty_per_guest) * (1 - discount_pct / 100)`.
- Для N гостей кількість кожного товару:
  `quantity = MAX(minimum, ROUND(qty_per_guest * guests) + qty_fixed)`.
- Загальна сума за добу:
  `total = SUM(product.unit_price(quantity) * quantity) * (1 - discount_pct / 100)`.

### AC-3. Віджет комплектів на вітрині (за макетом 04-event.html)
- Відображення перемикача кількості гостей: 50, 100, 200 (радіокнопки `k-seg`) та посилання на індивідуальний розрахунок.
- Картки 3 рівнів (`Базовий`, `Стандарт` з бейджем `Найчастіше беруть`, `Преміум`).
- Для кожної картки:
  - Ціна за гостя (`95 ₴ / гість`);
  - Загальна вартість на обрану кількість гостей за добу (`9 500 ₴ за 100 гостей · доба`);
  - Список включених та виключених предметів з іконками `i-check` та `i-minus` (`is-off`);
  - Кнопка «Додати до події» (`k-btn`).
- При перемиканні кількості гостей числа оновлюються миттєво без перезавантаження сторінки (ванільний JS).

### AC-4. Пакетне додавання комплекту в кошик
- Клік на кнопку «Додати до події» відправляє AJAX POST-запит на `extension/kristal/kit/add`:
  - Параметри: `kit_id`, `guests`.
  - Сервер перевіряє активність комплекту, розраховує всі товари та викликає `$this->cart->add($product_id, $qty)` для кожної позиції.
  - Повертає JSON `{success: true, count: N, redirect: "/order"}`.
  - Клієнт показує індикацію додавання та плавно скеровує у кошик події або оновлює лічильник кошика в шапці.

### AC-5. Сторінка події «Весілля» (`/vesillya`)
- Створення контролера сторінки події `extension/kristal/kit/event` (з SEO URL `vesillya`):
  - Hero-блок із заголовком «Оренда посуду на весілля», фактами (від 95 ₴, доставка й монтаж, 15 хв) та кнопками дій.
  - Блок комплектів `#sets`.
  - Блок додаткових послуг («Все, крім гостей»: стільці Chiavari, круглі столи, шатра, персонал).
  - Галерея сервірувань («Реальні весілля»).
  - Відгуки молодят та FAQ про оренду на весілля.
  - Форма захоплення ліда `#lead` («Розрахунок за 15 хвилин» на базі `kristal_lead`).

### AC-6. Адмінка «Крістал: комплекти»
- Розділ у головному меню: «Каталог → Комплекти для подій» (`extension/kristal/kit`).
- Список комплектів із фільтрацією за типом події та статусом.
- Форма додавання/редагування:
  - Тип події, рівень, назва, бейдж, знижка %;
  - Таблиця товарів: автокомпліт пошуку товару за назвою, кількість на гостя, фіксована кількість;
  - Редактор пунктів списку переваг (`k-list`).
