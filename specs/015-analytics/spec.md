## Проблема
1. На сайті відсутня наскрізна e-commerce та лід-аналітика: неможливо відстежувати ефективність рекламних кампаній, джерела заявок та воронку замовлення.
2. Не відстежуються кліки на кнопки дзвінка, Viber та Telegram, через які надходить значна частина запитів.
3. Відсутній банер згоди на кукі (Consent Mode v2), що створює ризики блокування трекінгу в сучасних браузерах.

## Мета і метрика
1. Повна фіксація всіх кроків клієнта у `window.dataLayer`:
   - `view_item` (перегляд товару)
   - `add_to_cart` (додавання товару або комплекту в кошик)
   - `begin_checkout` (перехід до оформлення на `/order`)
   - `purchase` (успішне замовлення на `/success`)
   - `generate_lead` (успішна відправка форми ліда «Розрахунок за 15 хв» або замовлення в 1 клік)
   - `contact_click` (кліки на `tel:`, `viber://`, `https://t.me/`)
2. Підтримка Google Consent Mode v2 (`analytics_storage`, `ad_storage`, `ad_user_data`, `ad_personalization`) та легкий неблокуючий банер згоди на кукі.
3. Можливість налаштування GTM ID (`GTM-XXXXXXX`) та GA4 ID (`G-XXXXXXXXXX`) в адмінці OpenCart.

## Критерії приймання
- **AC-1.** При вказанні GTM ID у налаштуваннях модуль підключає GTM контейнер з відкладеним або асинхронним завантаженням без блокування рендерингу (LCP не погіршується).
- **AC-2.** Перегляд картки товару генерує `dataLayer.push({ event: 'view_item', ecommerce: { ... } })`.
- **AC-3.** Додавання товару чи комплекту в кошик генерує `dataLayer.push({ event: 'add_to_cart', ecommerce: { ... } })`.
- **AC-4.** Сторінка успішного замовлення генерує подію `purchase` із переліком куплених позицій, номером замовлення та сумою.
- **AC-5.** Відправка форми ліда генерує `generate_lead` із типом форми та сумою (якщо відома).
- **AC-6.** Кліки на телефонні номери, Viber та Telegram відправляють `contact_click` із вказанням каналу зв'язку.

## Нефункціональні вимоги
- Нульовий вплив на PageSpeed: розмір аналітичного скрипту < 4 КБ, відсутність сторонніх важких бібліотек.
- Сумісність із PHP 7.3 та 8.3.
