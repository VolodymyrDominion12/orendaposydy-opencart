# 04 — Резервні копії і відновлення

Фіча 017 (`specs/017-security`). Бекап живе на хостингу **поза сайтом** — `~/kristal-backup/`,
з інтернету його не відкрити.

| Що | Як часто | Скільки зберігається | Файл |
|---|---|---|---|
| База | щодня о 03:17 | 14 останніх | `~/kristal-backup/db/db-<дата>.sql.gz` |
| Файли сайту (без кешу, сесій, логів, прев'ю) | раз на тиждень | 4 останні | `~/kristal-backup/files/files-<дата>.tar.gz` |
| Журнал | кожен запуск | — | `~/kristal-backup/backup.log` |

Пароль до бази скрипт читає з бойового `config.php` — після зміни пароля нічого правити не треба.

## Налаштування (один раз)

```bash
make backup-install      # заливає скрипт і друкує рядок для cron
```

cPanel → **Cron Jobs** → «Cron Email» — ваша пошта (лист прийде, лише якщо бекап упав) →
**Add New Cron Job**: хвилина `17`, година `3`, решта `*`, команда:

```
/bin/bash $HOME/kristal-backup/kristal-backup.sh
```

Наступного ранку: `make backup-status` — має бути 1 дамп бази й 1 архів файлів, у журналі без «ПОМИЛКА».

## Перевірка раз на місяць (і відновлення локально)

```bash
make backup-status       # свіжий дамп не старший 2 днів, журнал без помилок
make backup-pull         # найновіший дамп → dumps/prod-db-<дата>.sql.gz
make import              # локальна база = прод на дату дампу (з локалізацією пошти/оплат)
make test-smoke          # сайт відкривається
```

Запишіть дату перевірки в `specs/017-security/tasks.md` (T13) — так видно, що бекап не лише
робиться, а й відновлюється.

## Відновлення на проді (аварія)

1. **Не панікувати й нічого не видаляти.** Зробіть ще одну копію поточного стану: phpMyAdmin → Експорт.
2. **База:** cPanel → File Manager → `kristal-backup/db/` → завантажте потрібний `db-<дата>.sql.gz` →
   phpMyAdmin → база сайту → Імпорт → цей файл (gzip phpMyAdmin розпакує сам).
   Великий файл не проходить за лімітом phpMyAdmin — напишіть у підтримку HOSTiQ, вони імпортують із файлу.
3. **Файли** (якщо зламано код чи зникли фото): File Manager → `kristal-backup/files/` →
   правою кнопкою на архіві → **Extract** у домашню теку → з'явиться тека `orendaposydy.com/`
   (поверх наявної — лише потрібні підтеки: `image/catalog/`, `catalog/`, …).
   Кеш після цього: адмінка → Панель стану → шестерня → «Оновити».
4. `make test-smoke BASE=https://orendaposudu.com` і `make test-security BASE=https://orendaposudu.com`.

Код теми й модулів є ще й у git — для коду швидше `make deploy-apply SINCE=<тег>`.

## Чого тут немає

- Копії поза хостингом. Якщо хостинг втратить акаунт цілком — рятує лише те, що ви завантажили
  (`make backup-pull FILES=1` раз на місяць на свій диск або Google Drive) + git.
- Автоматичних бекапів самого HOSTiQ (JetBackup) — уточніть у підтримці, чи вони є в тарифі й за скільки днів.
