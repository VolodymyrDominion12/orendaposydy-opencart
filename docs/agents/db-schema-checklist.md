# Чек-лист: зміна схеми бази даних

Обов'язковий для кожної міграції в `db/migrations/`. Копіюй у `plan.md` фічі й відмічай.

## Перед написанням міграції

- [ ] У `plan.md` описано: які таблиці/колонки/індекси, навіщо, які запити ними користуватимуться.
- [ ] Перевірено, чи немає вже потрібної колонки/таблиці в ядрі OpenCart або модулях (`make db-tables`, `db/schema.sql`).
- [ ] Для ядрової таблиці — лише додавання (індекс або колонка з `DEFAULT`), без перейменувань і видалень.

## Файл міграції

- [ ] Назва `NNNN_slug.up.sql` + `NNNN_slug.down.sql` (NNNN — наступний номер, 4 цифри).
- [ ] Усі таблиці через `{{PREFIX}}`, жодного жорсткого `oc_`.
- [ ] Ідемпотентність: `CREATE TABLE IF NOT EXISTS`, `DROP ... IF EXISTS`, `ADD COLUMN IF NOT EXISTS`, `ADD INDEX IF NOT EXISTS` (MariaDB ≥ 10.0/10.1 це підтримує).
- [ ] Нова таблиця: `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci`, `PRIMARY KEY`, назва `{{PREFIX}}kristal_*`.
- [ ] Типи: id — `INT(11)` як у ядрі (для JOIN типи мають збігатися!), гроші — `DECIMAL(15,4)` як `price` у ядрі, дати — `DATETIME`/`DATE`, прапорці — `TINYINT(1)`.
- [ ] `down` повністю повертає попередній стан і не видаляє ядрові дані.
- [ ] Без `FOREIGN KEY` на ядрові таблиці (вони можуть бути MyISAM) — цілісність через код + індекс.

## Індекси

- [ ] Для кожного запиту з `plan.md`: колонки з `WHERE` (рівність), потім діапазон, потім `ORDER BY` — один складений індекс.
- [ ] Кожна колонка, по якій робиться `JOIN`, проіндексована (першою в індексі).
- [ ] Унікальні бізнес-ключі — `UNIQUE` (`uq_*`): напр. `keyword` редиректу.
- [ ] Новий індекс не є лівим префіксом наявного (і навпаки) — `make db-check` покаже.
- [ ] Не індексувати колонки з 2–3 значеннями самостійно (status) — лише як частину складеного.
- [ ] Для `VARCHAR(255)` в utf8mb4 у складеному індексі — перевірити ліміт довжини ключа (InnoDB 3072 байти) або префікс `col(191)`.

## Після застосування

- [ ] `make migrate` — без помилок; `make migrate-status` показує версію як застосовану.
- [ ] `make db-check` — немає нових рядків у звіті (порівняй з попереднім запуском).
- [ ] `make db-schema-diff` — диф = рівно те, що в міграції.
- [ ] `make db-explain` для кожного запиту з `plan.md` — використовується очікуваний індекс (`key` не `NULL`, `type` не `ALL`).
- [ ] `make migrate-down V=NNNN && make migrate` — відкат і повторне застосування проходять.
- [ ] `make db-schema-snapshot` — оновлений `db/schema.sql` у тому самому комміті.
- [ ] Для проду: `make migrate-print V=NNNN > /tmp/NNNN.sql` → `make deploy-sql SQL=/tmp/NNNN.sql`, бекап бази перед виконанням.
